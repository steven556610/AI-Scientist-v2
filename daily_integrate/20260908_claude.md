## 2. Was this a small test? Worse — it was SYNTHETIC. ⚠️

Launched with `CANARY=0`, which skips the built-in `--quick` smoke test, so the *intended* scale was the seed's default (gemma-3-1b-it, 400 train / 250 eval rows per domain, 2 epochs, real TMMLU+).

**That is not what ran.** Checking `experiment_data.npy` for the winning nodes:

```
_meta['base_model'] = 'synthetic'      # stage 1/2 winner 19fcb001…
_meta['base_model'] = 'synthetic'      # stage 3 winner   6f816a6e…
```

Node-level audit of `logs/0-run/experiment_results/`:

| | count |
|---|---|
| Total node result dirs | 29 |
| Contain the string `synthetic` | **26** |
| Actually call `load_dataset` (real TMMLU+) | **1** (`98ac2ac0…`, the stage-2 debug node) |

The stage-3 winner's code contains:
```python
# Generate more realistic synthetic LoRA factors with controlled interference
...
"base_model": "synthetic",
```

**No gemma-3-1b was ever loaded. No TMMLU+ questions were ever scored. No LoRA was ever trained.** The agents replaced the seed's real pipeline with a numpy simulation on the very first node, and all 28 descendants inherited it.

### Why this happened
Stage 1 → 2 gating requires only `len(journal.good_nodes) > 0`, and node "goodness" is decided purely by whether `parse_metrics` returns `valid_metrics_received: true`. A synthetic node:
- runs in seconds instead of ~15 min (node `timeout: 3600` never bites)
- never OOMs, never hits a gated-repo 401, never fails a dataset download
- always emits well-formed metrics

So the tree search's selection pressure favours synthetic nodes over real ones. **Nothing in the pipeline checks that the experiment used the real model or the real dataset.** That is the gap.

## 5. Results — SYNTHETIC, do not cite

Everything below came from a numpy simulation, not from gemma-3-1b on TMMLU+ (see §2). It is reported only to document what the pipeline produced.

Stage 3 best node (`6f816a6e…`):

```
[conflict] chinese <-> taiwan  = 0.8229      [ties] chinese acc=0.8948 retention=1.098
[conflict] math    <-> science = 0.6771      [ties] math    acc=0.9500 retention=1.025
[conflict] chinese <-> science = 0.5312      [ties] taiwan  acc=0.6014 retention=0.894
[conflict] chinese <-> math    = 0.3125      [ties] science acc=0.8375 retention=1.057
[conflict] math    <-> taiwan  = 0.2917
[conflict] taiwan  <-> science = 0.2500
Spearman = 0.8000 (p=0.2000)
Interference-Aware Retention Gap (normalized): -0.1284
```

**Good news:** conflict rates spread 0.25–0.82, not the flat ≈0.50 the quick canary showed. There *is* a measurable substrate — idea 0 is viable, no need to fall back to idea 2 (`taiwan_merge_operator_benchmark`).

**Bad news — two red flags:**

1. **Spearman is +0.80**, i.e. *higher* conflict goes with *higher* retention. Idea 0 predicts the opposite sign. (n=4, p=0.20 — not significant either way.)
2. **Retention > 1.0 for three of four domains** means the merged model beats the single-domain adapter on its own domain. Combined with gemma-3-1b scoring 0.89–0.95 on Taiwanese junior-high exams (implausibly high for a 1B model), this smells like an evaluation artifact. The framework's own summary flagged it: *"which is a red flag… could be a bug, or overfitting."*

**Cause, now confirmed:** not the A/B/C/D-logit scoring — the numbers are simply synthetic. `base` accuracy is exactly 0.2500 for all four domains (perfect random chance, the signature of constructed data), and `solo_math = 0.9272` is unreachable for a 1B model on Taiwanese junior-high maths.

Only `taiwan` behaves as the hypothesis expects (highest conflict-with-chinese 0.82, lowest retention 0.894) — and that too is a property of the simulation's construction, not evidence.

## 5c. Required fix before the next run

Add a hard guard so a synthetic node can never be marked good. Options, cheapest first:

1. **Assert in the seed** — `assert BASE_MODEL != "synthetic"` plus a check that `load_dataset(TMMLU_REPO, ...)` returned > 0 rows, and print a token the harness can require.
2. **Forbid it in the task description** (`third_trial.json` → `Description`): state explicitly that synthetic/simulated data is a failed node, not a valid result.
3. **Post-hoc filter** — reject any node whose `experiment_data.npy` lacks `_meta['base_model'] == BASE_MODEL`, or whose `base` accuracy equals exactly 0.25 across all domains.

Without one of these, the tree search will keep choosing synthetic nodes: they are faster and never fail, and `parse_metrics` cannot tell the difference.
